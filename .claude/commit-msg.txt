fix: never default to removing a git-tracked file, and drop displayName

Two findings from the real-install verification, both of the kind only a real
install produces.

**`--uninstall` pre-selected git-tracked repo state.** Run inside a repo, the
inventory listed `.graphifyignore` and the project-scope plugin rows — read out of
a **committed** `.claude/settings.json` — all checked by default. Pressing Enter
would have dirtied the working tree. The enumeration was right and the removals
were right; only the default was wrong, which is exactly the class of thing a unit
test with fixtures cannot notice.

`Item.tracked` now marks a row whose removal edits a file git tracks in the
current checkout, and those start **unselected**, rendered `[ ]`. Machine state
still starts selected — the user asked to uninstall, and re-naming each piece
would turn a cleanup into a quiz — but dirtying a checkout is not a cleanup.

That forced the prompt's semantics to change: the numbers now **toggle** rather
than meaning "keep". With two possible defaults there are two directions to move a
row in, and "enter what to keep" leaves no way to ask for the one row that is off.
`--dry-run` resolves the same defaults, so it describes the run you would get by
pressing Enter rather than a wider one. `tracks()` answers via
`git ls-files --error-unmatch`, and an unknown answer is **false** — a machine
without git must not quietly stop offering to clean itself.

**`displayName` fails `claude plugin validate --strict`.** The renderer emitted it
for years; Claude reports it as an unknown field it *ignores at load time*, and
`--strict` — the mode its own help recommends for CI — fails on it. I had seen it
missing from the schemastore schema earlier and kept it on the reasoning that it is
"what users see as the marketplace name". That reasoning was wrong: it is seen by
nobody. `name` is the name. Removed from the generator, with a test asserting it
stays gone.

And since Claude's validator knows something no checker here can — which fields it
actually reads — `plugins:check` now runs `claude plugin validate --strict` over
the marketplace manifest and all 13 plugins. **Skipped with a warning when `claude`
is absent**, so a container without the agent CLI can still validate a plugin tree;
a silent pass would be worse than not running it.

Also removed the untracked `renderer/` and `schema/` directories, left behind
holding nothing but `node_modules` after their packages were deleted.
