## North star

The repo converges on **two plugins**:

- **`vwf`** — the workflow for building a product (Product → Blueprint → Plan →
  Execute → Verify/Feedback) **plus the curated engineering doctrine**: the
  principles catalog this plan adds, alongside the existing baseline.
- **`stackgen`** — the tool that makes a product *executable*: it materializes
  project-level skills/agents/conventions for the user's declared stack, and it
  **configures** the supporting machinery with the AI tool — LSP servers, MCP
  servers, hooks, repo gates. Configure, not conjure: stackgen wires existing
  servers and tools; it does not implement them.

Every other plugin merges into stackgen (see the merge waves). The closed stack
menu retires: the durable value is principles, which most developers don't
apply; how to use any particular stack is researchable.

## The dispatch rule (core architecture)

Given a project's declared stack, stackgen resolves each technology in order:

1. **Pre-created pack first.** This repo ships curated stack packs as stackgen
   **assets** (`plugins/stackgen/stacks/…` — assets, not live plugin skills, so
   installing stackgen floods no session with every stack's doctrine). A covered
   technology is **copied** from its pack into the project — never generated.
2. **Generation only for what no pack covers.** Uncovered technologies go
   through the pipeline: Context7 research → instantiate the principles catalog
   → the reviewer gate → the same materialized tree.

Both paths land in **`.agents/`** at the repo root — the single committed,
**repo-owned** tree for everything stackgen materializes (skills, agents,
conventions). The project may edit its copies; collaborators need no plugin
installed for them to work. Claude Code wiring is **symlinks**:
`.claude/skills/<name>` → `../../.agents/skills/<name>` (and likewise
`.claude/agents/`), created by stackgen and committed.

**Re-sync is explicit.** A stackgen sync run diffs the repo's copies against the
current packs (and offers regeneration for generated entries) and presents the
delta for consent — drift is visible, never silently overwritten.

## Phase 1 — The principles catalog (vwf)

The curated core; independently valuable whatever follows.

- `engineering-baseline.md` stays the 15 enforced rules. A new
  `plugins/vwf/assets/principles/` library adds one reference per principle:
  KISS, YAGNI, DRY (and its limits), the five SOLID principles, information
  hiding (Parnas), design by contract, idempotency, explicit error semantics,
  least privilege.
- Fixed shape per entry: **definition → smells → how a reviewer verifies it →
  application patterns → when NOT to apply it** (the anti-rubber-stamp defense).
- Entries link to — never duplicate — `engineering-baseline.md`,
  `minimalism.md`, the karpathy guidelines, and `rest-api-design`.

## Phase 2 — The stackgen plugin core

- **`stackgen-stack-menu` / `stackgen-stack-template`** (model-invocable) — the
  adapter seam. The menu lists the shipped packs plus one open entry: *generate
  for anything uncovered*. First pin runs the dispatch; later fetches
  (`plan`/`execute`'s conventions read) return the materialized, committed
  conventions from `.agents/`. Materialization is explicit — never a silent
  re-run.
- **The materializer**: pack copy → `.agents/` + the `.claude/` symlinks; the
  facts `doctor` needs (per-language LSP, mise tool, manifest shape) emitted
  into the template payload from the pack's metadata.
- **The generator** (uncovered only): detect the real stack (manifests +
  graphify) → Context7 research → instantiate the catalog, citations mandatory →
  `stackgen-skill-reviewer` agent (stateless: catalog + skill + citations in,
  gaps out; loop until clean) → the same `.agents/` tree. Context7 unreachable →
  **halt, never guess**.
- **The sync skill**: the explicit re-sync described in the dispatch rule.
- **Consent**: the full materialized set as a dry-run plan; one commit on
  approval, via the git workflow.
- **Mechanism check, early**: verify Claude Code discovers skills through
  `.claude/skills/` symlinks before building on it; if it does not, the fallback
  is sync-maintained copies with the same ownership rules — the `.agents/` tree
  stays authoritative either way.
- Phase 2 ships the machinery with **no packs yet** — packs arrive in the merge
  waves; until then the curated plugins remain the covered-stack path (that is
  the parallel track), and stackgen's value is the uncovered tail.

## Phase 3 — vwf accommodations

1. **The materialized escape** in `stack-vocabulary.md` + doctor's stack checks:
   a language is known when the project's pin is a stackgen template carrying
   emitted facts; doctor verifies against those facts. The unknown-language
   blocking stays for projects with neither.
2. **Catalog handover**: `architecture`/`setup` pass the principles-catalog
   asset paths into the stackgen invocation. No cross-plugin file reaching.
3. **`stack-adapter.md`** documents the materialized-template variant and the
   `.agents/` tree.

## Phase 4 — Prove it

Full loop against a scratch project on an uncovered stack (e.g. Go + chi +
sqlc): dispatch falls through to generation, reviewer + consent, `.agents/` +
symlinks, doctor passes on emitted facts, `plan`/`execute` read the conventions.
Docs ship with the change (`docs/plugins/stackgen.md`, readme, CLAUDE.md). **The
merge waves start only after this evidence, and each wave needs its own
go-ahead.**

### Phase 4 evidence (2026-08-19)

> Recorded before the post-execution revision: the symlink findings below proved
> a mechanism the `.claude/`-direct design no longer needs (the auto-apply
> result carries over — the skill fires the same way as a plain
> `.claude/skills/` directory). The generation/reviewer/doctor/fetch legs stand
> unchanged.

**Revision proof (2026-08-19, Rust).** The revised design was re-proven
end-to-end against a scratch Rust 2021 + axum 0.8 + cargo fixture, kind
`language-bundle`: real Context7 research (`/tokio-rs/axum`,
`/websites/doc_rust-lang_cargo`; tokio/serde disclosed as un-researched, with no
API claims made about them); the reviewer gate (seven checks then, kind
conformance included; coverage became the eighth) returned **NO GAPS in round
1** — the Go run's citation/detection disciplines, applied up front, converged
immediately; the **dry-run consent gate ran for real** (8-file landing set,
settings.json explicitly untouched, user approved); landing wrote skills +
references + a rule + payload + citations + `lock.yaml` with content hashes; the
real CLI then **auto-applied the generated skill on a `.rs` edit and fired the
`Cargo.toml` rule verbatim**; the payload fetch parsed back pure-read; doctor's
escape resolved `rust` as known via `language_facts`; and the sync demo
classified a deliberate edit as REPO EDITED by hash while a hand-written skill
outside the lockfile stayed invisible to sync.

Run against a scratch Go 1.24 + chi v5 + sqlc/pgx v5 project (an uncovered stack
— no installed plugin claims `go`):

- **Symlink mechanism check, twice against the real CLI**: a plain skill
  symlinked `.claude/skills/<name>` → `../../.agents/skills/<name>` was listed
  and available in a `claude -p` session; the generated, paths-scoped
  `go-chi-sqlc` skill **auto-applied on a `.go` edit** through the same symlink.
  The copies fallback stays documented, unused.
- **Dispatch fell through to generation**: no pack covers the stack; the
  pipeline ran detect (go.mod, sqlc.yaml) → real Context7 research
  (`/go-chi/docs`, `/websites/sqlc_dev_en`, `/jackc/pgx`) → catalog
  instantiation with inline citations.
- **The reviewer gate earned its keep**: six fresh stateless rounds, eight
  verified gaps found and fixed — an unemitted `Querier` claim, restated
  API-reference material, missing/unsupporting citations (including one where
  the cited when-not-to-apply clause argued the opposite), an undisclosed
  research source, and a harness mechanism that could not do what it claimed —
  before `NO GAPS`.
- **Doctor's materialized escape**: token `go` resolved as **known** via the
  entry's `language_facts` (gopls provision, mise tool `go`, manifest `go.mod` —
  verified present); without the escape it would have been unknown = blocking.
- **The conventions fetch is a pure read**: frontmatter + body parsed back into
  the full template payload (axis, platforms, languages + facts, harness with
  six capabilities, 96-line conventions prose) with no research, network, or
  write.

## Phase 5 — The merge waves (12 plugins → stackgen), individually gated

- **Wave A — machinery and registries.** What stackgen *ships and configures*:
  the LSP declarations from `typescript` and `flutter` merge into stackgen's
  manifest as a per-language registry (inert until matching files exist); the
  Claude Design MCP server + the three design-adapter skills from
  `design-tools`; the npm→pnpm/bun hook; the `devtools` scaffold + repo-gate
  doctrine. vwf's one dependency flips `devtools` → `stackgen`.
- **Wave B — capability contracts.** `datastore`, `identity`, `observability`,
  `orchestration`, `object-storage`: the neutral contracts join the curated
  knowledge stackgen instantiates; their named providers (Postgres, OIDC,
  OTel-LGTM, Temporal) become **packs**.
- **Wave C — stacks become packs.** `typescript`, `flutter`, `cicd`, `gcp`,
  `cloudflare`: the judgment prose and the stack templates become **pre-created
  packs** under `plugins/stackgen/stacks/` — the dispatch rule's preferred path
  — and the closed menu retires.
- **Wave D — retirement.** The twelve plugin directories are deleted, the
  marketplace shrinks to `vwf` + `stackgen` (installing `vwf` pulls `stackgen`
  as its one native dependency; the CLI wrapper's `--all` resolves to the pair),
  and the language-plugin contract
  (`.claude/skills/plugin-authoring/references/language-plugins.md`) is archived
  as the record of the replaced model.

## Risks

- **Symlink support** is load-bearing and unproven — hence the Phase 2 mechanism
  check with a copies fallback. Windows checkouts materialize symlinks as text
  files; accepted (this toolkit already assumes a POSIX/macOS toolchain), noted
  in stackgen's docs.
- **Pack drift** — a repo-owned copy diverges from an upgraded pack by design;
  the explicit re-sync diff is what keeps it visible.
- **Rubber-stamping a bad stack choice** — mitigated by the catalog's
  when-not-to-apply sections and the reviewer gate.
- **Thin Context7 coverage** on niche stacks — the generator says so rather than
  padding.
- **The merge waves are the deep water** — live machinery moves in Wave A; each
  wave ships with the docs and doctor updates it implies, and Wave D happens
  only when nothing curated is still load-bearing.
