## North star

The repo converges on **two plugins**:

- **`vwf`** — the workflow for building a product (Product → Blueprint → Plan →
  Execute → Verify/Feedback) **plus the curated engineering doctrine**: the
  principles catalog this plan adds, alongside the existing baseline.
- **`stackgen`** — the tool that makes a product *executable*: it generates the
  project-level skills/agents/conventions for the user's declared stack, and it
  **configures** the supporting machinery with the AI tool — LSP servers, MCP
  servers, hooks, repo gates. Configure, not conjure: stackgen wires existing
  servers and tools; it does not implement them.

Every other plugin merges into stackgen (see the merge waves). The closed stack
menu — which forces this repo's stack choices onto users — retires in favor of
generation: the durable value is principles, which most developers don't apply;
how to use any particular stack is researchable.

## Decisions (settled in brainstorm, 2026-08-17)

| Decision    | Ruling                                                                                                                                                                                                                    |
| ----------- | ------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------- |
| Positioning | **Parallel during build, merge as the end state.** Curated plugins keep working until their merge wave lands; the convergence to vwf + stackgen is the committed goal                                                     |
| Home        | **New adapter-shaped plugin** (`stackgen`) implementing the existing stack-adapter contract, so vwf's flow needs minimal change                                                                                           |
| Catalog     | **Extends vwf's baseline** — one canonical principles home as vwf assets; vwf passes it into the stackgen invocation (design-adapter payload style)                                                                       |
| Output      | **Neutral source + emit** — generated skills land in a committed neutral tree (`.skills/`), emitted to `.claude/skills/`. **[revisit]** the neutral tree existed for multi-target portability, which Claude-first retired |
| Trust gate  | **Reviewer agent + user approval** — every generated skill is checked against the catalog and its citations, then lands only through a dry-run consent gate                                                               |

## Phase 1 — The principles catalog (vwf)

The curated core; independently valuable whatever follows.

- `engineering-baseline.md` stays the 15 enforced rules. A new
  `plugins/vwf/assets/principles/` library adds one reference per principle:
  KISS, YAGNI, DRY (and its limits), the five SOLID principles, information
  hiding (Parnas), design by contract, idempotency, explicit error semantics,
  least privilege.
- Fixed shape per entry: **definition → smells → how a reviewer verifies it →
  application patterns → when NOT to apply it** (the anti-rubber-stamp defense).
- Entries link to — never duplicate — `engineering-baseline.md`,
  `minimalism.md`, the karpathy guidelines, and `rest-api-design`.

## Phase 2 — The stackgen plugin core

- **`stackgen-stack-menu` / `stackgen-stack-template`** (model-invocable —
  `disable-model-invocation: false`, Claude's spelling of what the retired
  neutral manifest called `invocation: both`) — the adapter seam. One menu
  entry: *generate for this project's declared stack*. First pin runs the
  pipeline; later fetches return the already-generated, committed conventions.
  Generation is explicit — never a silent re-run.
- **Pipeline**: detect the real stack (manifests + graphify) → research each
  technology via Context7 → instantiate the catalog into per-technology project
  skills, citations mandatory → emit the facts `doctor` needs (per-language LSP,
  mise tool, manifest shape).
- **`stackgen-skill-reviewer` agent** — stateless: catalog + generated skill +
  citations in, gaps out. Loop until clean.
- **Consent**: full generated set as a dry-run plan; one commit on approval.
- **Emit**: `.skills/` → `.claude/skills/` — see the Output row's **[revisit]**.
- Context7 unreachable → **halt, never guess**.

## Phase 3 — Minimal vwf accommodations

1. **The generated escape** in `stack-vocabulary.md` + doctor's stack checks: a
   language is known when the project's pin is a stackgen template carrying
   emitted facts; doctor verifies against those facts.
2. **Catalog handover**: `architecture`/`setup` pass the catalog paths into the
   stackgen invocation. No cross-plugin file reaching.
3. **`stack-adapter.md`** documents the generated-template variant.

## Phase 4 — Prove it

Full loop against a scratch project on a stack no curated plugin covers (e.g.
Go + chi + sqlc). Docs ship with the change (`docs/plugins/stackgen.md`, readme,
CLAUDE.md). **The merge waves start only after this evidence.**

## Phase 5 — The merge waves (12 plugins → stackgen)

Each wave is its own reviewed change; curated plugins keep working until their
wave lands.

- **Wave A — machinery and registries.** The pieces stackgen *ships and
  configures* rather than generates: the LSP declarations from `typescript` and
  `flutter` merge into stackgen's manifest as a per-language LSP registry (inert
  until matching files exist); the Claude Design MCP server and the three
  design-adapter skills from `design-tools`; the npm→pnpm/bun hook; the
  `devtools` scaffold + repo-gate doctrine (mise, dprint, eslint, gitleaks,
  grype, pre-commit, docker, doppler). vwf's one dependency flips `devtools` →
  `stackgen`.
- **Wave B — capability contracts.** `datastore`, `identity`, `observability`,
  `orchestration`, `object-storage`: their neutral contracts are
  principle-shaped and join the curated knowledge stackgen instantiates; their
  named providers (Postgres, OIDC, OTel-LGTM, Temporal) become generation seeds
  rather than shipped skills.
- **Wave C — stack and platform judgment.** `typescript`, `flutter`, `cicd`,
  `gcp`, `cloudflare`: the judgment prose (which service when, billing, IAM, the
  house build pipeline) becomes stackgen's curated knowledge base — pre-verified
  seeds the generator prefers over raw research when the user's stack matches;
  the stack templates and the closed menu retire.
- **Wave D — retirement.** The twelve plugin directories under `plugins/` are
  deleted, the marketplace shrinks to `vwf` + `stackgen` (installing `vwf` pulls
  `stackgen` as its one native dependency, which is what `--all` used to express
  — Claude-first retired the flag along with the CLI's plugin installer), and
  the language-plugin contract
  (`.claude/skills/plugin-authoring/references/language-plugins.md`) is archived
  as the record of the model this replaced.

## Sequencing

Claude-first plan → Phases 1–4 (one commit each) → merge waves A–D (one reviewed
change each), with Phase 4's evidence as the gate before Wave A.

## Risks

- **Rubber-stamping a bad stack choice** — mitigated by the catalog's
  when-not-to-apply sections and the reviewer gate.
- **Generated skills going stale** on stack upgrades — regeneration is an
  explicit re-run, diffed against the committed `.skills/` tree.
- **Quality variance** on stacks with thin Context7 coverage — the generator
  says so rather than padding; Wave C's curated seeds cover the stacks this repo
  already knows deeply.
- **The merge waves are the deep water.** Wave A moves live machinery (LSP, MCP,
  hooks, the scaffold vwf depends on) and must not break existing vwf installs;
  each wave ships with the docs and doctor updates it implies, and Wave D
  happens only when nothing curated is still load-bearing.
