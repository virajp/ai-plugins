# Plan: stackgen — the principles-driven skill generator

**Status: proposed — awaiting approval. Nothing in this plan is built.**

## Why

The language-plugin model forces this repo's stack choices onto users: the
typescript menu offers Effect/Hono/Astro/Refine, and a user wanting anything
else is blocked by the closed menu rather than served by it. The durable value
this repo provides is not stack doctrine — how to use any particular stack is
researchable — but the engineering principles most developers don't actually
apply: KISS, YAGNI, DRY and its limits, SOLID, information hiding (Parnas),
design by contract, idempotency, explicit error semantics, least privilege.

stackgen inverts the model: curate the principles, generate the stack
realization. Given a project's *declared* stack (whatever the user chose), it
researches the technologies via Context7 and writes reviewed, committed,
project-level skills that instantiate the principles catalog for exactly that
stack.

## Decisions (settled in brainstorm, 2026-08-17)

| Decision    | Ruling                                                                                                                                                                          |
| ----------- | ------------------------------------------------------------------------------------------------------------------------------------------------------------------------------- |
| Positioning | **Parallel track.** The curated language plugins stay untouched and authoritative for their stacks; stackgen is a second path. Retirement/reframing only after it proves itself |
| Home        | **New adapter-shaped plugin** (`stackgen`) implementing the existing stack-adapter contract, so vwf's flow needs minimal change                                                 |
| Catalog     | **Extends vwf's baseline** — one canonical principles home as vwf assets; vwf passes it into the stackgen invocation (design-adapter payload style)                             |
| Output      | **Neutral source + emit** — generated skills land in a committed neutral tree; a light emit step projects them per configured target                                            |
| Trust gate  | **Reviewer agent + user approval** — every generated skill is checked against the catalog and its citations, then the set lands only through a dry-run consent gate             |

Approvable defaults: plugin name `stackgen`; neutral tree
`.skills/<name>/SKILL.md` (Agent Skills-standard layout, committed); catalog at
`templates/vwf/assets/principles/`.

## Phase 1 — The principles catalog (vwf)

The curated core, and the hardest authoring work. Independently valuable even if
later phases stall.

- `engineering-baseline.md` stays the 15 enforced rules. A new
  `templates/vwf/assets/principles/` library adds one reference per principle:
  KISS, YAGNI, DRY (and its limits), the five SOLID principles, information
  hiding, design by contract, idempotency, explicit error semantics, least
  privilege.
- Fixed shape per entry: **definition → smells → how a reviewer verifies it →
  application patterns → when NOT to apply it**. The last section is the
  anti-rubber-stamp defense: a generator that derives doctrine from the user's
  choice must also know when the choice itself is the smell.
- Every entry links to — never duplicates — `engineering-baseline.md`,
  `minimalism.md`, the karpathy guidelines, and `rest-api-design` where they
  overlap.
- vwf minor version bump; docs reconciled.

## Phase 2 — The stackgen plugin

`templates/stackgen/` — deliberately **not** a language plugin (no `languages:`
key), so the language-plugin contract does not bind it.

- **`stackgen-stack-menu` / `stackgen-stack-template`** (`invocation: both`) —
  the adapter seam. The menu offers one entry: *generate for this project's
  declared stack*. The template skill runs the generation pipeline on first pin;
  on later fetches (`plan`/`execute`'s conventions read) it returns the
  **already-generated, committed** conventions from the repo. Generation happens
  once, explicitly — never silently re-run.
- **The generation pipeline**: detect the project's real stack (manifests +
  graphify) → research each technology via Context7 → instantiate the catalog
  into per-technology project skills ("how *explicit error semantics* is
  realized in *this* Go + chi service", citations mandatory) → emit the facts
  `doctor` needs (per-language LSP, mise tool, manifest shape) into the template
  payload.
- **`stackgen-skill-reviewer` agent** — stateless: catalog + generated skill +
  citations in, gaps out (uncited facts, misapplied principles, invented
  claims). The generator loops until the reviewer returns clean.
- **Consent gate**: the full generated set is presented as a dry-run plan;
  nothing lands without approval, then one commit via the git workflow.
- **`stackgen-emit`**: projects `.skills/` into `.claude/skills/` first; Cursor
  / OpenCode / Oh-My-Pi emitters are later work, deliberately deferred.
- Context7 unreachable at generation time → **halt, never guess** (the same rule
  as the stack-template conventions fetch).

## Phase 3 — Minimal vwf accommodations

Three contained edits; everything else already works because stackgen speaks the
existing stack-adapter contract.

1. **The generated escape** in `stack-vocabulary.md` + doctor's stack checks: a
   language is also *known* when the project's pin is a stackgen-generated
   template carrying emitted facts — doctor verifies against those facts instead
   of a claiming plugin. The unknown-language blocking stays for projects with
   neither a claiming plugin nor a generated pin.
2. **Catalog handover**: `architecture`/`setup` pass the principles-catalog
   asset paths into the stackgen invocation, the same payload style the design
   adapter uses. No cross-plugin file reaching; no stackgen dependency on vwf.
3. **`stack-adapter.md`** documents the generated-template variant.

## Phase 4 — Prove it, then document it

- Run the full loop against a scratch project on a stack no curated plugin
  covers (e.g. Go + chi + sqlc) — the honest test, since nothing curated can
  bail it out.
- Docs ship with the change: `docs/plugins/stackgen.md`, readme + CLAUDE.md
  rows, and a note in the language-plugin contract
  (`.claude/skills/plugin-authoring/references/language-plugins.md`) that the
  parallel generated track exists.

## Sequencing

Phases land in order, one commit each. Phase 1 first — it improves every vwf
project today regardless of what follows.

## Risks

- **Rubber-stamping a bad stack choice** — the failure mode inverts versus the
  closed menu (which fights user choice). Mitigated by the catalog's
  when-not-to-apply sections and the reviewer gate.
- **Generated skills going stale** on major upgrades of the project's stack.
  Regeneration is an explicit re-run, diffed against the committed tree — the
  neutral source being committed is what makes staleness visible.
- **Quality variance across stacks** — the reviewer checks citations and
  principle fidelity, but a niche stack with thin Context7 coverage produces
  thin skills. The generator must say so rather than pad.
- **Dual-path maintenance** during the parallel period: the curated plugins and
  stackgen coexist by design; the exit criteria (adopt, reframe plugins as
  pre-generated instances, or retire the experiment) are decided after Phase 4
  evidence, not before.
