# Decisions — the renderer rename, the HTTP transport, palace hygiene

**Date** 2026-08-14 · **Branch** `main` (worked in place, by request) ·
**Commits** `1a8a275`, `7de7d95`, `64e70f9`

Mirrors the mempalace drawer (wing `ai-plugins`, room `decisions`); both stores
written together, per `templates/vwf/assets/memory.md`.

## Why `build/` became `renderer/`

`build` is in mempalace's **hardcoded `SKIP_DIRS`** (`palace.py`), beside `dist`
and `node_modules`. In this repo that directory was **source** — the render
pipeline — not output, so it was unmineable and **no `exclude_patterns` entry
could opt it back in**. Only a rename could.

`renderer/` also mirrors the split the repo already documents: `renderer/` is
the build-time, pure half; `cli/` the install-time, effectful one.

Two of the path rewrites were **inside strings the renderer emits** — ohmypi's
`Generated by @ai-plugins/…` banner and `cursor.ts`'s generated header — plus
`mempalace-checkpoint.sh`, which is copied byte-for-byte. So 15 files in the
rendered trees moved with it. Verified by a real mine: **328 drawers under room
`renderer`, where `build/` had produced 0.**

## Why mempalace stays on HTTP — and why the old reason is gone

The Chroma-era argument was the **single writer lease**. It no longer applies:
`palace.py:413` declares
`_MULTI_PROCESS_WRITER_BACKENDS = frozenset({"pgvector", "qdrant"})`, so on
Qdrant `backend_requires_single_writer()` returns false and `daemon.py` never
takes the lease. Concurrent processes are safe **at the store**.

What kills stdio anyway, on every backend:

- `_save_hallways` (`hallways.py:122-146`) rewrites `hallways.json` **whole**
  behind an atomic `os.replace` and takes **no lock**. One daemon serializes
  those writes in-process; N stdio processes race and last-writer-wins silently
  drops entity edges. It is local JSON beside the palace — Qdrant never sees it.
  Tunnels are the same shape.
- stdio spawns one server **per client session**, each holding its own ~140 MB
  embedder and paying its own model warm-up.

The stale claim had been copied to four places; all four now carry the real
reason. **Re-litigate only if upstream locks that write path.**

## Operational facts that live nowhere else

**Qdrant collection names are namespace-prefixed.** The real names are
`mempalace_c0655d864595323b_mempalace_drawers` / `_closets`, the hash derived
from the palace path. A `PUT` against the bare `mempalace_drawers` returns `ok`
and does nothing. Keyword payload indexes on `metadata.wing` and `metadata.room`
took faceting from `HTTP 400` — a client-side scan fallback that had been
drifting since 08-13 — to **12 ms**. **Nothing in mempalace creates these**, so
a rebuilt or second palace starts with none, and the only symptom is slowness,
never an error. `metadata.source_file` left unindexed by choice.

**Deleting a wing: filter on `wing`, never on source path.** The `graphify_out`
wing (7,818 drawers + 39 closets, all `graphify-out/cache/ast/*.json`) came from
a mine run *inside* that directory — no `mempalace.yaml` there, so the wing
became the directory name. `graphify-out/` sits **inside** the repo tree, so a
path-prefix delete would have taken all 4,998 `ai-plugins` drawers with it.
Follow any external delete with `mempalace_reconnect`: it ran in a separate
process and the daemon caches metadata.

**`~/.mempalace/config.json` had a stale `palace_path`** (`~/.mempalace/palace`,
which does not exist). It worked only because `MEMPALACE_PALACE_PATH` is
exported in the shell — any context without it (launchd, cron, a container)
would have silently created a fresh empty palace. Repointed, and `backend` +
`qdrant_url` added, since fixing the path alone would have given the right
directory with the **wrong backend**. **Precedence trap:** config-file `backend`
**wins over** env `MEMPALACE_BACKEND` — the reverse of `palace_path`, where env
wins.

## Left undone, deliberately

- `metadata.source_file` payload index — the third field mempalace filters on.
- `topic_wings` / `hall_keywords` in `~/.mempalace/config.json` are still
  upstream's defaults (`emotions`, `family`, keyed on "scared", "cry", "love"),
  tuned for a personal journal rather than a code palace. Inert, but they are
  what inflates `hallways.json` to 213 KB.
- `.config/mise/tasks/code/count` still excludes `*/build/*` as a generic output
  pattern, so `renderer/` is now counted where `build/` was not. The number is
  more accurate; it will look like a jump.
